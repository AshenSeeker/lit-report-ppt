# 版式硬参数（从真实汇报稿量出来的，别凭感觉改）

来源：一份 28 页的组会汇报稿，逐形状量取。
这套数字不是审美偏好，是**已经被验证能上台**的几何。改之前先问：改成什么、为什么。

`scripts/lr_common.py` 顶部的常量就是这张表的代码版本 —— **改参数改那里，别在 build_deck.py 里硬编码**。

## 画布

| 项 | 值 |
|---|---|
| 尺寸 | 13.333 × 7.5 in（16:9，宽屏） |
| 母版 | 南阳师范学院物电学院（校徽横条 + 底部水波纹） |
| 内容页版式 | `空白`（index 6），纯白，所有元素手工放 |
| 封面/致谢版式 | `标题和内容`（index 1，带底部水波纹） |

EMU 换算：1 in = 914400 EMU。python-pptx 用 `Inches()` 就行。

⚠️ 版式 `标题和内容` 的 layout 背景是 `bg2`（E7E6E6 灰），但渲染出来是纯白 —— 因为母版 `clrMap` 里 `bg2=lt2`，实际不显灰。**不要手动 set_bg 去"修"它**，会破坏水波纹层。

## 字体（本机可用）

| 用途 | 字体 | 说明 |
|---|---|---|
| 英文正文、图注、公式 | Times New Roman | 论文血统，图注必须这个 |
| 中文标题/标签/说明 | 楷体 | 原稿用 `华文楷体`，本机没有，用 `楷体`（simkai） |
| 序号 ①②③④ | 等线 | 原稿实测就是这个 |
| 封面校名条 | Verdana | 英文校名，别换 |

⚠️ **中英混排要拆 run**。`Cs2NaInCl6 掺杂` 不能整段套一个字体 —— python-pptx 会按第一个 run 的 east-asian 字体渲染。规则：拉丁字符走 Times New Roman，汉字走楷体，并且东亚字体必须显式写 `<a:ea typeface="楷体">`。
`lr_common.add_runs()` 已按字符集自动拆分，直接用它。

## 字号梯级

原稿只有 11 / 16 两档，图注和正文一样大，投出去看不清 —— 这是要修的。

| 层级 | 常量 | 字号 | 用在哪 |
|---|---|---|---|
| H0 封面主标题 | `L.H0` | 66pt | 只有「文献汇报」四个字 |
| H1 页标题 | `L.H1` | 22pt | 章节页大字、文章首页右侧卡标题 |
| H2 小标题 | `L.H2` | 18pt | 段落标题、副标题 |
| B1 正文 | `L.B1` | 16pt | 摘要精读、方法段落 |
| B2 提炼框 | `L.B2` | 14pt | 补充说明、概念卡、术语白话解释 |
| C1 图注 | `L.C1` | 11pt | 论文图注（译成中文），一字不减 |
| C2 脚注 | `L.C2` | 10pt | 来源标注 |

`check_deck.py` 的白名单是 `{66,60,40,22,20,18,16,14,13,11,10}`，出现别的字号会报。

**相邻两级之间不出现 1.2 倍以内的关系**：11→14 是 1.27（两档语义不同：论文原文 vs 我的提炼）；14→18 是 1.29；18→22 是 1.22。真正的层级跳是 11 → 16 → 22 → 66。

## 主图页 —— 两种排法，按「放不放得下」自动选

不是按字数阈值，是**真的算行数**：`lr_common.caption_lines()` 用 `est_text_width × 1.20 / (box_w - 0.08)` 估行数，`CAP_LINE_H=0.186` 估行高（11pt 楷体行高，含 1.25 倍行距）。

```python
_, tail = L.split_caption(cap_text, FIG_A_CAP[2], FIG_A_CAP[3])   # 底栏放得下 → A
if not tail: return "A"
_, tail = L.split_caption(cap_text, FIG_B_CAP[2], FIG_B_CAP[3])   # 右栏放得下 → B
if not tail: return "B"
return "B"                                                        # 两栏都放不下 → B + 续页
```

**A. 底栏图注**（短图注，原稿 P9/P12/P17 就是这个）
```
图片区   (0.61, 0.15)   11.71 × 6.20   等比 contain 居中
图注栏   (0.72, 6.44)   11.80 × 0.92   11pt 楷体
```

**B. 右栏图注**（长图注，原稿 P8/P16/P21/P26）
```
图片区   (1.35, 0.16)    8.45 × 7.16   等比 contain 居中
图注栏   (9.95, 0.14)    2.75 × 7.14   11pt 楷体
```

### 图注续页（`_caption_overflow`）

两栏都放不下时，**自动开续页，续页上必须是完整的「图 + 注」**，不能只有注。

```
标题     (0.95, 0.30)   11.30 × 0.34   「图 5（续）」14pt 粗 灰
图       (1.60, 0.70)   10.10 × 3.55   同一张图再放一遍
图注     (0.95, 4.48)   11.30 × 2.70   11pt 楷体，行距 1.30
```

⚠️ `split_caption` 的 `size` 必须和 `write_box` 写字用的字号一致。曾经按 11pt 估、用 16pt 写，估得下、渲染却出界。

### 表格页（`build_table`）

原稿是一张 10.29 × 2.84 的光板表浮在页面正中，没有标题也没有章节标签 —— **照原样保留**（用户明确说"样本外元素全删，严格照样本"）。

```
表格宽    10.29（可被 spec["width"] 覆盖）
左边距    (13.333 - width) / 2
上边距    1.62（spec["top"] 可覆盖）
行高      0.62（spec["row_height"] 可覆盖）
列宽      按 est_text_width 估算，首列 +0.30
对齐      列宽 > 内容宽 × 1.8 → 居中，否则数字右对齐
图注      表格下方 0.18in 处
```

⚠️ 列宽如果等分，「3.8 %」这种窄内容会占掉半个页面 —— 必须按内容估算。
⚠️ python-pptx 没有边框 API，要往 `tcPr` 塞 `a:ln`。**CT_TableCellProperties 子元素顺序是固定的**：`lnL,lnR,lnT,lnB,lnTlToBr,lnBlToTr,cell3D,<fill>,headers,extLst`。插错位置 PowerPoint 报文件损坏。做法：找第一个 fill/headers/extLst 当 anchor，然后 `addprevious`。`lr_common.cell_border()` 已封装。

### 姓名与时间缺省值

`build_cover` 和 `build_thanks` 都调 `who_line(meta)`：

```python
who  = (meta.get("presenter") or "").strip() or "XX"
when = (meta.get("date") or "").strip() or "XX"
→ "汇报人：XX      时间：XX"
```

**没给就写 XX，绝不替我编一个人名或日期。** 用户提前说了姓名/时间，就写进 `content.json` 的 `meta`，或者命令行 `--presenter "张三" --date "2026年11月2日"`。

## 上下角标

**必须用真正的上下标格式，不是 Unicode 字符。**

`Cr³⁺` 这种 Unicode 上标换个字体就散架，复制到论文里会变成乱码。

内容源里写成 `Cr^{3+}` / `Cs_{2}NaInCl_{6}`，`add_runs()` 会转成带 `baseline` 属性的 run：
- 上标 `baseline="30000"`
- 下标 `baseline="-25000"`
- 字号自动 ×0.72

Word 那边用 python-docx 原生的 `run.font.superscript = True`。

这是规范图第 7 条点名要的（「提前适应上下角标等复杂格式调整」）。

⚠️ `check_deck.py` 检查字号时会跳过带 `baseline` 的 run —— 因为上下标字号是主动缩到 8pt 的，不能当违规报。
